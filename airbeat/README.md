# 凌空节拍 AirBeat · MVP 原型

策划案 v0.1 里 **MVP（11-28）** 这一档的落地：手机 / PC 浏览器原型，4 鼓、击打发声、三层力度、1 首曲，判定层回放测试通过。

没有 Rokid 实机和 Unity 环境，所以用浏览器 + 摄像头 + MediaPipe Hands 做。按策划案 5.1 的说法：它只能验证逻辑，不能验证手感。

## 运行

```bash
cd airbeat
npm start          # python3 -m http.server 8080，然后打开 http://localhost:8080
npm test           # 判定层单元测试 + 回放测试（Node 22，无依赖）
```

必须通过 http 打开（ES 模块和谱面 JSON 不能走 file://）。摄像头需要 localhost 或 https。

三种输入：

- **摄像头手势**：MediaPipe Hands 在本机识别双手，画面不上传。首次加载要从 CDN 下载约 17MB 的模型和运行库。
- **鼠标 / 触屏**：指针当作一只手，向下划过鼓面即击打。键盘 D F J K 直接敲四面鼓（Shift 为重击）。
- **加载回放日志**：播放录下来的手部数据。`test/fixtures/` 里有一份合成样例。

URL 参数：`?debug=1` 显示采样率、音频延迟、校准值；`?offset=90` 覆盖设备固定偏移（毫秒）；`?predict=0` 关闭预测触发；`?lead=20` 设置预测提前量。

## 和策划案不一样的地方

- **布局一字排开**。普通摄像头没有可靠深度，田字的前后两排分不开，所以把 4 面鼓摊成一排，间距保持 19cm。田字和 8 鼓的坐标已经写在 `layouts.js`，等实机用。
- **世界尺寸是假设**。画面宽度固定当作 0.8m。离摄像头远近不同，速度读数会成比例偏差，靠三次试挥校准抹平。
- **1€ 滤波参数**：`dCutoff` 取常见的 1Hz 时，滤波滞后让穿越时刻晚约 15ms；现在取 20Hz，合成轨迹上误差在 5ms 内。这组值是在合成数据上调的，真实追踪噪声下要重调。
- **设备固定偏移**：摄像头模式下，浏览器给出采集时间戳时取 20ms，否则取 90ms。两个数都是估计值，没有实测。

## 没做的

MVP 范围之外的都没做：8 鼓玩法、降级提示、AI 合奏、难度自适应、云端点评（结算页用的是本地模板）、演示模式、编辑模式、暂停手势。

## 验证情况

- `npm test`：34 项全过。包含整首 1 星谱面的回放（37 个音符，无误触发、无漏判）。
- 无头 Chromium 里用鼠标和键盘走通了全流程：校准、自由练习、整首曲、结算。
- 摄像头模式只验证到"模型加载成功、识别循环在跑"。**真人的手没有测过**，判定点、握拳检测阈值、固定偏移都需要在真实摄像头前调。
